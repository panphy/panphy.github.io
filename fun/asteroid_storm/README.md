# Asteroid Storm

The game behind `fun/asteroid_storm.html`: a pixel-art dodger with no shooting. Every image, the font, the music and the sound effects are made in code; there are no asset files.

- `main.js`: game loop, stages, hazards, capsules, input and the initials dialog.
- `art.js`: palette, ship sprite, procedural asteroids, capsules, the 5 × 7 bitmap font, nebulae, stars and planets.
- `audio.js`: Web Audio sound: an original chiptune track for each stage (`SONGS`: key, tempo, chords, melody, instruments and drums) and the effects. A new stage's track starts on the next downbeat at least 0.45 s away; the old one fades to a third of its volume under a rising whoosh, and the new one fades back up over 0.9 s.
- `leaderboard.js`: the Top Survivors board.
- `joystick.js`: the pixel-art touch pad shown below the game on narrow touch screens, or beside it on phones held sideways (where the game fills the screen height). It drags the ship like a finger on the field does, but `PAD_GAIN` (1.8) times as far; a tap on it starts, resumes or restarts a run.
- `title.js`: the animated pixel-art title banner.
- `pilot.js`: the pilot portrait under the leaderboard, drawn only when the side columns are beside the game (1000 px and wider). Each expression is a set of numbers (eye openness, brows, mouth...) that ease toward their target, so faces step through in-between shapes. `main.js` sends one-off events through `react()` (close call, capsule, shield, mini, shockwave, hit) and, every frame, `frame()` with the danger, the nearest rock's side and what is active (capsules, black holes, flares, comet warnings, god mode, which turns the eyes gold and adds a golden aura). The resting face turns tense with the stage and crowding.
- `trophies.js`: the 16 trophies (milestones, pixel-art badges and physics facts) and the trophy case beside the board. Full Set needs all six capsule types.

Cloudflare keeps stylesheets and scripts at its edge for up to four hours, so the page loads them with a version query (`?v=YYYYMMDD-name`): in `fun/asteroid_storm.html` for `style.css` and `main.js`, and in the `import` lines of `main.js`, `trophies.js`, `title.js` and `joystick.js`. Change it everywhere at once whenever any of these files changes, or visitors can get a new page with old styles or code.

## Difficulty

Every control shares one top speed, `SHIP_SPEED` (320 px/s), so no device has an edge: the keyboard moves at it; a mouse over the field and a finger on it (the ship held `TOUCH_LEAD` above the fingertip) set a target the ship flies to at up to that speed; the touch pad moves that target by the thumb's movement times `PAD_GAIN`. Between runs (title, pause, game over) a finger starts or resumes a run only with a tap, and a swipe on the field scrolls the page. Speeds, sizes and hitboxes are all in the field's 360 × 240 pixels, so the size the game is shown at changes nothing: in full screen on a screen at least 1000 px wide, `fitFullscreen` lays the page out at the width (1000 to 1700 px) that shows the game biggest without shrinking the panels below 90%, then scales the whole page as one picture to fill the screen.

The asteroid curve (speeds, spawn rate, sizes, hitboxes) grows with the stage at a rate set by `RAMP`. The world advances in fixed 1/120 s steps whatever the frame rate, so speeds, collisions and the clock are the same on every device. A stage lasts 20 seconds. Comets and gravity wells (black holes) start in Stage 2, the first well 2.5 seconds in; splitting rocks and solar flares start in Stage 3. A flare is a loop of flame that arcs out of one edge of the field and back into it, as solar flares erupt along magnetic loops: blinking dashed lines mark the loop, drawn through the ship's position, for 1 second, then it blazes for half a second. Only the marked band can hit the ship; the flame tongues past it are for show. Each black hole and each flare gets its own size between a minimum and a maximum (`WELL_SIZE`, `FLARE_HALF_RANGE`); a bigger black hole has a bigger core, reach and pull. `RAMP` and the stage hazard intervals are tuned with a bot that reads the warnings: its median run is about 100 seconds. Capsules give a shield, slow time (for 5 seconds), a mini ship (much smaller, and 1.7 times the top speed and touch-pad reach, with an afterimage trail, for 7 seconds), a shockwave that throws rocks within 130 px away without destroying them, radar (dotted lines showing where rocks and comets are heading, for 7 seconds) or autopilot. Autopilot flies the ship for 5.5 seconds, ignoring the player's steering: it scores nine directions by their clearance over the next third of a second, cruises near the middle once clear, and the ship cannot be hit meanwhile. It blinks for its last second, then the player has a second of safety; skill trophies (close calls, flares, black holes) are not earned while it flies. They come more often in later stages (every 10 to 14 seconds in Stage 1, down to 7 to 9 in Stage 5: `capsule` in `STAGES`), but a shield never appears while one is held or within `SHIELD_COOLDOWN` (15) seconds of the last; after that a capsule is a shield with `SHIELD_CHANCE` (1 in 7), and the other five kinds share the rest equally. A capsule is never the same kind as the one before it. Slow time also slows the clock, so it never pads a score. `STAGES` and the constants at the top of `main.js` hold the numbers.

## Leaderboard

Scores (survival times in seconds) are read from the `dodge_leaderboard` table and written only through the `submit_dodge_score` function, both in the "PanPhy Games" Supabase project rather than in this repository. The page uses plain REST calls with the public anon key. The function and a table constraint (`dodge_survival_time_range`) accept only 1 to 600 seconds; `MIN_SCORE` and `MAX_SCORE` in `leaderboard.js` match them, so raise all three together if a legitimate run could exceed 600 seconds. `.github/workflows/supabase-keepalive.yml` also queries the table twice a week so that the free-tier project is not paused.

A run in which the testing cheat (god mode) was switched on is unranked: it saves no personal best and is never offered for submission. The cheat code is stored only as a hash (`TRAIL_PHASE_SEED`), as in KeyFire.

To reset the board after a gameplay change: copy the table into the `backup` schema (`create table backup.dodge_leaderboard_YYYYMMDD as table public.dodge_leaderboard;`), check that the row counts match, then run `delete from public.dodge_leaderboard;`. In the same change, bump `CACHE_KEY` in `leaderboard.js` and add the old key to `OLD_CACHE_KEYS`, so browsers drop their saved copy of the old board.

## Trophies and callouts

Trophies are kept only in this browser (localStorage: `dodgeTrophiesV1`, `dodgeTrophiesSeenV1`, and `dodgeCapsulesSeenV1` for Full Set, which counts only the current six kinds), never on the server, and are not earned in a run that used god mode. They do not affect the leaderboard. The trophy case's "Clear local records" button (after a confirmation) forgets the trophies and the personal best on this device; the online leaderboard is untouched. A new trophy slides into the top-right corner of the field, and stays highlighted in the trophy case until opened. Close calls show a callout under the timer, bigger for closer passes; close calls within 3 seconds of each other build a streak, and the game-over screen shows the best streak.
